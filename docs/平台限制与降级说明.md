# 平台限制与降级说明

> 对照对象：原版 [aegis-vault](https://github.com/keaidang/aegis-vault)（Python / FastAPI 单体 + 本地文件系统）。
> 本文件只记录**在 EdgeOne Makers 上做不到、或只能降级实现**的能力，以及对应的补偿设计；能力清单与实现状态见 README。

## 1. 做不到 / 只能降级

| # | 能力 | 原版怎么做的 | 为什么在 EdgeOne 做不到 | 现在的方案 |
|---|---|---|---|---|
| 1 | **服务端校验口令 / 确认码强度** | `validate_password_strength`（≥12 位）与 `validate_code_strength`（≥8 位）都在服务端拿到明文后校验 | 明文永不出浏览器（端到端加密的前提），服务端只拿到 PBKDF2-SHA256 派生值，无法反推原始口令、签到码或胁迫码 | 长度/复杂度校验放在前端：口令 ≥12 位、签到码与胁迫码 ≥8 位；服务端只校验派生值是否存在。直接构造 `/api/init`、`/api/codes/*` 请求可绕过前端校验（只能影响自己即将初始化的库） |
| 2 | **笔记正文无上限** | 写本地文件 | Edge Functions 请求体上限 **1MB**（JSON） | 正文密文上限 900KB（约 750KB 明文），超限返回 413；大内容走附件（R2 预签名直传） |
| 3 | **分钟级定时自毁** | 后台线程每 5 分钟扫描 | 免费套餐 cron 最低 **1 天/次**，且 schedules 不支持自定义请求头 | **访问即检**：任何 `/api/state`、登录、签到都会检查超时并立即销毁；每日 03:15 cron 只兜底"无人访问"的情况。最长延迟 24h 仅发生在完全无人访问时 |
| 4 | **会话即时失效** | 进程内会话字典，删即失效 | 边缘函数无状态，会话落 KV，而 KV 边缘缓存最长 **60s** | 登出/改密会删 KV 会话键；旧 Cookie 最坏在 ≤60s 窗口内仍可能被某个边缘节点接受。另设**会话滑动空闲上限 10 分钟**（`SESSION_IDLE_SEC`，前端 5 分钟本地锁定在前，服务端兜底在后），避免 Cookie 在 12h TTL 内被拷走后长期可用。**真正的保护是销毁时先删密钥**，密文立即变成废料 |
| 5 | **精确失败限流** | 内存计数 + 锁 | KV 无原子自增，且最终一致 | 15 分钟窗口 5 次失败（登录/签到各自计），属**弱限流**，并发请求可能绕过 |
| 6 | **审计序号原子递增** | 本地文件 + 文件锁 | KV 无原子操作 | `get → +1 → put`，高并发下可能重号，链校验会报异常。单管理员日常使用不会触发 |
| 7 | **安全擦除 / mlock / 文件权限** | OS 能力（shred、mlock、chmod） | 无文件系统、无内存锁；R2 删除对象 ≠ 物理擦除 | 客户端加密 + **先删密钥后删密文**：删钥后任何残留密文都不可解；平台侧备份/快照不在本项目控制范围内 |
| 8 | **实时同步 / 长连接** | 常驻进程，可推 WebSocket/SSE | 边缘函数无状态、无长连接 | 倒计时由前端本地计算 + `/api/state` 拉取；多标签页之间不同步 |
| 9 | **请求之外的后台任务** | 任意线程/定时器 | 只有 schedules；`waitUntil` 仅限当前请求生命周期 | 大清理分批执行（R2 每次 1000 个对象），中断则下次重扫（幂等） |
| 10 | **>64MB 单文件** | 原版上限就是 64MB | 分片直传需要逐片签名 + 前端并发编排，当前实现是单次 PUT | 与原版保持一致：单文件上限 **64MB**，不支持更大 |
| 11 | **R2 桶的 CORS / 公开访问策略** | 无此问题 | 桶配置在 Cloudflare 侧，代码无法下发 | **部署时必须手工配置 CORS**（见《部署配置指南》§4），否则浏览器直连预签名 URL 会失败 |
| 12 | **`SESSION_SECRET` 轮换** | 重签本地文件即可 | 状态 HMAC 校验失败会被判定为"状态被篡改"，进而触发自毁 | **初始化后不要更换 `SESSION_SECRET`**；确需更换，先销毁并重新初始化 |
| 13 | **边缘侧生成 RSA-4096 / 大文件加解密** | 服务端进程内完成 | Edge Functions 单次请求 CPU 约 200ms | 密钥生成、文件分块加解密全部放浏览器；服务端只做 HMAC-SHA256 / SHA-256 / AES 包裹校验这类轻量运算 |
| 14 | **使用 Blob 存笔记** | 无（本地文件） | Blob SDK 只在 Node 函数可用，而 Node 函数拿不到 KV 绑定 | 放弃 Blob：笔记正文/标题/附件名走 KV，图片附件走 R2 |
| 15 | **"假仓库"（duress decoy）** | 曾有设计（假数据掩人耳目） | 需要额外的写入路径与密钥派生，且与"立即销毁"的语义冲突 | **不做 decoy**：命中胁迫码即真销毁（先删钥），对外只返回与他人完全一致的"身份验证失败"。`crypto.js` 里的 `deriveFileKey` 仅保留作回归用例，运行时未使用 |
| 16 | **并发写锁定** | 进程内 `RLock`（`notes_manager.NOTES_LOCK`、`audit_logger.audit_lock`）串行化写入 | KV 无锁、无事务，读改写无法保证原子性 | 笔记正文/索引/审计计数采用"最后写入胜出"：同一篇笔记被两个标签页同时保存时可能丢一次修改；单管理员顺序操作不会触发 |
| 17 | **无 JS / 无 WebCrypto 降级** | 服务端渲染 + 表单 POST，禁用 JS 也能完整使用 | 密钥派生、加解密全部发生在浏览器（WebCrypto） | 必须使用支持 WebCrypto 的现代浏览器（Chrome/Edge 90+、Safari 16+）；禁用 JS 或旧浏览器完全不可用——这是"明文永不出浏览器"的必然代价 |

## 2. 与原版语义一致、实现方式不同

| 交互 | 原版 | 现在 |
|---|---|---|
| 下载 / 删除文件、查看 / 删除笔记、附件操作 | 表单内嵌口令字段，服务端逐次校验 | 行内口令输入框（同原版位置）+ `/api/verify`（服务端 180s 窗口）；输入框留空时退回浏览器 prompt |
| 文件名 / 笔记标题 / 附件名 | 服务端可见明文 | 一律 AES-GCM 加密，服务端不可见；笔记列表在浏览器内解密标题 |
| 四用户槽位、管理员管理协议、签到/胁迫、5 分钟空闲锁定、链式审计 | 服务端会话 / 本地文件 | 语义保持一致，状态与会话落 KV |
| 口令 / 确认码校验算法 | `scrypt`（服务端保存哈希） | PBKDF2-SHA256 × 600,000（浏览器派生，`info` 区分 login/checkin/note）+ 服务端只比对派生值 |
| 页面形态与笔记深链接 | Jinja 服务端渲染，`/notes?note=<id>`、`?note=create` 表示当前笔记 | 静态页 + `/api/*`；深链接语义一致（`/notes.html?note=<id>`、`?note=create`），选笔记时用 `history.replaceState` 同步 URL |
| 笔记「详细信息 → Modification History」 | `modification_history` 保留最近 200 个时间戳，倒序展示 | 相同：保存时追加时间戳、保留最近 200 个，页面按 UTC+8 倒序显示 |

## 3. 原版有、当前未实现

| 项 | 说明 |
|---|---|
| 历史审计归档的浏览入口 | 每日 cron 把前一日日志写入 R2 `archive/audit-<date>.jsonl`（写入前校验链完整性），页面只展示最近 300 条实时日志；归档文件需到 R2 控制台取回，没有页面下载入口 |
| 审计日志按事件类型筛选 | 原版 `get_audit_logs(event_type=...)` 有服务端过滤参数（其页面也没有暴露）；本版固定返回最近 300 条，只能在页面上人工筛 |

> 笔记标题解密、附件文件名/上传时间、修改记录 200 条、`?note=` 深链接等此前缺失的原版行为已补齐，回归见 §4。

## 4. 回归基线

```bash
node tools/api-smoke-test.mjs    # 45 项接口回归（含胁迫码、限流、CSRF、配额、笔记）
node tools/crypto-test.mjs       # 10 项加密回归
# 浏览器端：E2E 31 项 + 胁迫专项 9 项（需要本地桩服务器与 playwright-core）
```

> 上述限制若未来平台开放（例如 cron 支持分钟级、KV 提供原子自增），对应降级项可以直接升级，不影响前端契约。
