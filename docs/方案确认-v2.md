| 项 | v2.0 设计 | **实际实现** |
|---|---|---|

| 内部端点鉴权 | 请求头 `x-internal-token` | EdgeOne schedules **不支持自定义请求头**（仅 name/cron/timezone/method/path/payload）→ token 改由 `payload.token`（或 query）传入，三种通道都接受 |
| KV 列表 API | 按 Cloudflare `keys[].name` | EdgeOne 返回 `keys[].key` + `complete` + `cursor` → 代码双兼容并游标翻页（单页 256） |
| KV 一致性 | 秒级 | 官方为**边缘缓存最长 60s**，会话/状态读取按"可容忍陈旧"设计 |
| 文件名/附件名 | 密文 | v2.0 前端曾以 base64 占位，现已改为 AES-GCM 加密（服务端不可还原） |
| 重置流程 | 无 | `init` 增加守卫：已初始化且未销毁时必须携带与 `RESET_TOKEN` 一致的 `reset_token`；销毁态可直接重建 |
| 失败限流 | 设计提到"限流计数" | 登录/签到各 15 分钟窗口 10 次失败即 429（KV 最终一致下属弱限流） |
| 登录哈希盐 | — | 改为 per-vault 随机盐（`/api/state` 公开返回），旧部署缺省回退固定盐 |
| 安全头 | Phase 4 待办 | 已由 `edgeone.json` 的 `headers` 下发 CSP / HSTS / XFO 等 |
| 前端样式交付 | Play CDN（`cdn.tailwindcss.com`）+ Google Fonts `@import` | **Tailwind 本地预编译**（`public/css/tailwind.css`，~10KB）+ Orbitron 自托管；首屏 0 第三方请求 |
| 视图切换 | 模板服务端渲染 | CSS `.hidden` + JS 切换；`style.css` 里 `.hidden` 曾被误包进 `@media (max-width: 767px)` 导致桌面端失效，已修复 |
| 布局容器 | 视图直接挂在 `.auth-frame` 下 | 多一层 `#page-content` 包裹，已在 CSS 中补 `flex:1; min-height:0` 以保持原版固定高度 + 内部滚动 |

## 0. 本版确认的核心决策（相对 v1.0 的变更）

| # | 决策点 | v1.0 设计 | **v2.0 确认结果** |
|---|---|---|---|
| 1 | 文件存储 | 腾讯云 COS | **Cloudflare R2（S3 兼容）**，签名改 AWS SigV4；国际线路上传速度可接受，零下行流量费 |
| 2 | 笔记存储 | COS 对象 | **Makers 内置 Blob 存储**（单值 25MB），KV 只存索引 |
| 3 | 客户端加密 | 推荐 | **确认采用**：口令派生、密钥生成、AES-GCM 加解密全在浏览器 |
| 4 | 自毁机制 | schedules cron | **确认可行**：先删钥后删密文 + 前端本地兜底，见 §5 |
| 5 | 旧数据迁移 | 待定 | 云端全新初始化，旧数据不迁移 |
| 6 | KV 开通 | 待确认 | 已按"个人网站配置缓存/会话"口径提交申请（约 10MB、5 QPS） |
| 7 | 存储配额 | 无 | **可调配额 + 设置菜单**：保险库默认 5GB（可在菜单调整）；**笔记不占配额**（存 Blob，与配额体系无关） |
| 8 | 国内访问速度 | R2 无国内节点 | **日常访问不碰 R2**：页面/笔记/列表全走 EdgeOne 国内边缘（KV/Blob）；仅文件上传/下载瞬间经预签名 URL 直连 R2，国内高速体验不受影响 |
| 9 | R2 实测 | 设计 | **已实测通过（2026-10-11）**：Put/Get/Head/Delete/List 全链路 OK，测试脚本 `tools/r2-test.mjs` |

> **R2 专用桶（已就绪，2026-10-11 实测）**：专用桶 `edge-vault`（自定义域 `vault.keaidang.top`，建议关闭桶公开访问，全部走预签名 URL）。文件统一放 `vault/<user>/` 前缀下，自毁扫描只清 `vault/` 前缀。API Token 按桶授权（Object Read & Write），ListBuckets 403 属预期。实测脚本 `tools/r2-test.mjs` 全链路通过：Put/Get/Head/Delete/List/预签名。

### 存储配额设计

```
KV config:storage  →  { "vault_quota_bytes": 5368709120, "notes_excluded": true }
                       默认 5GB，UI「存储设置」菜单可调
KV usage:vault     →  { "used_bytes": ... }   上传成功后累加，删除后扣减
```

- 上传流程：`/api/upload/meta` 在签发预签名 URL 前，先校验 `used_bytes + 文件大小 ≤ vault_quota_bytes`，超限拒绝。
- 笔记正文/附件（Blob）不检查该配额，仅受 Blob 单值 25MB 限制。
- 配额菜单在 Phase 1 一并实现（读取 + 调整 config:storage、展示 used/quota 进度条）。

## 1. 最终架构

```
                        ┌────────────────────────────────────────────┐
                        │            EdgeOne Makers 站点              │
 浏览器 ──HTTPS────────>│                                             │
 （加密/解密全在此）      │  ┌────────────┐   ┌──────────────────────┐ │
                        │  │ 静态页面     │   │ 边缘函数 (JS)          │ │
                        │  │ index/notes/│   │ /api/* 路由            │ │
                        │  │ logs        │   │ auth/checkin/upload/  │ │
                        │  └────────────┘   │ notes/destroy/sweep   │ │
                        │                   └──────────┬───────────┘ │
                        │  ┌────────────┐   ┌──────────▼───────────┐ │
                        │  │ schedules   │   │ KV: 状态/会话/密钥/     │ │
                        │  │ cron 自毁    │   │     审计/笔记索引       │ │
                        │  │ + 归档       │   │ Blob: 笔记密文/附件     │ │
                        │  └────────────┘   └──────────────────────┘ │
                        └───────────────┬─────────────────────────────┘
                                        │ AWS SigV4 签名（WebCrypto 实现）
                                        ▼
                          ┌──────────────────────────┐
                          │  Cloudflare R2 桶（S3 兼容）│
                          │  文件密文 (AES-256-GCM)    │
                          │  审计日志归档              │
                          └──────────────────────────┘
```

**信任模型**：明文永不出浏览器。边缘函数只见密文与哈希；R2 侧无任何密钥材料——即使 R2 账号被查，拿到的也只是无钥废料。数据托管在境外 + 云端零密钥，隐私语义较原版增强。

## 2. 存储分工（三层）

| 层 | 承载内容 | 键/对象设计 |
|---|---|---|
| **KV**（`aegis-state` / `aegis-session` / `aegis-audit`） | 系统状态 + HMAC、会话 Token、限流计数（聚合落盘）、口令包裹的私钥（`key:<user>`）、签到/胁迫哈希、审计链（`audit:<seq>`）、**笔记索引 `notes-index:<user>`**（<100KB，含 note_id、加密摘要、Blob 指针） | 写配额核算：每日几百次，远低于 1 万次/天上限 |
| **Blob** | **笔记正文密文** `notes/<user>/<note_id>/body.aes`、**图片附件密文** `att/<id>.aes`（单值上限 25MB，覆盖笔记场景；写入不挤占 KV 写配额） | 读列表只查 KV 索引；打开/保存才读写 Blob |
| **R2（S3）** | **文件保险库密文** `vault/<user>/<file_id>.aes`（大文件走 SigV4 预签名 URL 直传/直下，浏览器直连 R2，边缘不经手数据）；审计日志日归档 `archive/audit-YYYYMMDD.jsonl` | Multipart 分块并行上传可吃满国际带宽 |

> R2 桶设置：关闭 Object Lifecycle 保留规则（保证删除即干净）；不开公开访问；S3 API endpoint `https://<account>.r2.cloudflarestorage.com`，SigV4 签名用 WebCrypto 的 HMAC-SHA256 实现，无需 SDK。

## 3. 密码学方案（确认）

| 项 | 方案 |
|---|---|
| 口令派生 | **浏览器端**（推荐任意强度；若服务端参与则 PBKDF2-SHA256 ≥60 万迭代） |
| 密钥对生成 | **浏览器端**（RSA-4096 生成在边缘必超 200ms CPU；浏览器生成不受限） |
| 文件加密 | AES-256-GCM 分块（每块 ≤256KB + 独立 nonce），明文不出浏览器 |
| 私钥格式 | `aegis-key-v3-edge`：派生密钥 + AES-GCM 包裹，存 KV |
| 签到/胁迫哈希 | PBKDF2 慢哈希（或客户端哈希后上传） |
| 状态防篡改 | HMAC-SHA256（WebCrypto） |
| R2 访问签名 | AWS Signature V4（HMAC-SHA256，WebCrypto 实现） |

## 4. API 设计（不变）

```
POST /api/init            首次初始化（浏览器生成密钥对，上传包裹私钥 + 哈希）

POST /api/destroy         手动销毁
POST /api/internal/sweep     schedules 自毁扫描（仅内部 token）
POST /api/internal/archive   schedules 审计归档（仅内部 token）
```

## 5. 自毁机制（已论证可行，双保险）

**主链路**（schedules cron 每 5 分钟）：

```
① 删 KV 密钥键 key:<user>          ← 先删钥！1~2 个键，最不易失败，
② R2 DeleteObjects 批量删密文        单次最多 1000 对象，几百文件 1~2 次调用
③ 清空 KV 其余键 + Blob 笔记密文
④ 写 destroyed 墓碑 + 审计记录
```

- 全 I/O 无 CPU 压力，不受 200ms 限制；流程幂等，中断则下周期重扫。
- **不可恢复性由①保证**：删钥后所有密文即废料，即使②失败实质上已"销毁"，②只是清尸体。

**前端兜底**：页面加载时本地检查 `last_checkin` 超时 → 清除浏览器缓存的密钥材料、拒绝提供解包服务。即使边缘平台整体失联，用户端也不会协助解密——这一点比原版 Python 后台线程自毁更强。

## 6. 安全语义对照

| 原语义 | 云上现实 | 补偿 |
|---|---|---|
| shred 介质擦除 | R2 删除非擦除 | 客户端加密 + 先删钥；密文即最后一道防线 |
| mlock 防落盘 | 平台管理内存 | 接受降级，文档明示 |
| 本地文件权限 | 无文件系统 | KV/R2 私有读写 + CAM/R2 Token 最小授权 |
| 单进程一致性 | KV 最终一致（秒级） | 会话以签发点为准；限流聚合计数 |
| 空闲锁定 | 60s 空闲登出（logout + 刷新） | 纯前端，改为 **5 分钟**本地锁定：只清内存私钥、保留服务端会话、不刷新页面（60s 会频繁把用户踢回登录页） |
| HTTPS | EdgeOne 强制 | 内置 |

## 7. 实施计划

**Phase 1 · 骨架**
- Makers 项目搭建：静态页面 + 边缘函数路由 + KV/Blob 绑定 + 环境变量（R2 AccessKey/SecretKey、内部 token）
- R2 桶创建 + API Token 最小授权
- `/api/init`、`/api/login`、`/api/checkin`、`state:system` 打通

**Phase 2 · 笔记与文件**
- 浏览器端加密库（AES-GCM 分块、RSA-OAEP、口令派生）
- 笔记：Blob 读写 + KV 索引（本版新增优先项）
- 文件：R2 SigV4 预签名直传/直下（Multipart 并行）、列表与删除

**Phase 3 · 自毁与审计**
- schedules 自毁扫描（先删钥后删密文）+ **前端本地超时兜底**（本版新增）
- 审计日志链式哈希 + 每日归档到 R2
- 端到端实测：手动改 last_checkin 超时 → 验证 KV/R2/Blob 全清 + 墓碑写入

**Phase 4 · 加固**
- CSP 安全头、胁迫码逻辑、前端 5 分钟空闲锁定、THREAT_MODEL.md 更新

**降级备选**：边缘 CPU 实测卡死 → Makers 全栈框架适配（Node 运行时），存储层设计不变。
