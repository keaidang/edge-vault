# Edge Vault 部署配置指南

> 部署前需要完成的所有控制台配置都在这一页。代码已就绪，按顺序操作即可。
> 平台侧做不到的能力、以及对应的降级设计，见 [平台限制与降级说明](平台限制与降级说明.md)。

## 1. 创建 Makers 项目并连接仓库

1. EdgeOne 控制台 → Pages/Makers → **创建项目** → 选择 **从 Git 仓库导入** → 选 `keaidang/edge-vault`
2. 框架预设选 **无框架 / 其他**；构建命令与输出目录**由仓库内 `edgeone.json` 接管**（`mkdir -p dist && cp -r public/* dist/`，输出目录 `dist`），控制台留空或用默认值即可
3. 部署分支：`main`

> 目录说明：边缘函数目录固定为 `edge-functions/`（路由 `edge-functions/api/[[default]].js` → `/api/*`），**不需要**改名。
> 注意：Edge Functions 单次请求体上限 1MB、CPU 200ms，所以笔记正文（JSON 上传）实际可用约 750KB 明文；大内容请走附件（R2 预签名直传）。
>
> 🎨 **CSS 是预编译产物**：`public/css/tailwind.css` 已提交进仓库，部署阶段**不需要** `npm install` / 不访问外网。只有当你新增/修改了 HTML、JS 里的 class 时，才需要本地跑一次 `npm install && npm run build:css` 再提交。

## 2. 创建并绑定 KV 命名空间（3 个）

控制台 → **KV 存储** →（如未开通先点申请开通）→ 创建以下 3 个命名空间，然后逐个 **绑定到项目** 并设置变量名（变量名必须完全一致，代码里以全局变量引用）：

| 命名空间名称 | 绑定变量名 | 用途 |
|---|---|---|
| `edge-vault-state` | `state_kv` | 系统状态/密钥材料/哈希/文件元数据/笔记/配额 |
| `edge-vault-session` | `session_kv` | 会话 Token |
| `edge-vault-audit` | `audit_kv` | 链式哈希审计日志 |

绑定路径：KV 存储页 → 命名空间 → 关联项目 → 绑定项目 → 填变量名；或项目详情 → KV 存储 → 绑定命名空间。

> ⚠️ **上线前必须验证键名字符集**：官方文档写明 KV key 只允许数字/字母/下划线，而本项目使用 `state:system`、`key:me`、`file:<id>` 这类键。请在预览环境执行一次 `await state_kv.put('probe:colon','1')` 与 `await state_kv.get('probe:colon')`：
> - 若成功：现网可用，无需改动；
> - 若被拒绝（400）：需要把 `[[default]].js` 里的键分隔符统一换成 `_`（如 `state_system`），并同步 `tools/api-smoke-test.mjs` 的断言。
>
> KV 为最终一致（边缘缓存最长 60s），会话/状态读取可能短暂陈旧；本项目已按"可容忍陈旧"设计（密钥删除后密文即废料）。

## 3. 配置环境变量

项目详情 → **环境变量**，添加以下全部条目：

| 变量名 | 值 | 说明 |
|---|---|---|
| `R2_ACCOUNT_ID` | `<你的 Cloudflare 账户 ID>` | Cloudflare 账户 ID |
| `R2_ACCESS_KEY_ID` | `<R2 API Token 的 Access Key ID>` | R2 API Token 的访问密钥 ID |
| `R2_SECRET_ACCESS_KEY` | `<你的 Secret Access Key>` | ⚠️ 务必勾选"加密/私密"类型 |
| `R2_BUCKET` | `<桶名，如 edge-vault>` | 专用桶 |
| `SESSION_SECRET` | （`openssl rand -hex 32` 生成） | 会话签名 + 审计链哈希密钥 |
| `INTERNAL_TOKEN` | （`openssl rand -hex 32` 生成） | schedules 调用 `/api/internal/*` 的鉴权 token |

生成密钥：`openssl rand -hex 32`，两个变量用不同的值。

> 🔑 **INTERNAL_TOKEN 要写进 `edgeone.json`**：EdgeOne schedules 不支持自定义请求头，只能通过 `payload` 传参，所以 `edgeone.json` 里两个定时任务的 `payload.token` 必须替换成与 `INTERNAL_TOKEN` **完全相同**的值（默认占位符 `REPLACE_WITH_INTERNAL_TOKEN` 会导致定时任务返回 403）。该 token 只用于触发"超时自毁"和"日志归档"，两者本身不具破坏性前提（未超时不会销毁），但仍建议不要把真实值提交到公开仓库——可在部署时用 CI 变量替换。
>
> 🔁 **忘记密码重置**：`POST /api/init` 在已初始化且未销毁时会拒绝重建。需要重置时，先在控制台临时加环境变量 `RESET_TOKEN=<随机串>`，页面点"忘记密码"输入同一个值完成重建，**随后立即删除该变量**。

## 4. R2 桶检查（已完成大半）

- ✅ 桶已建好，Token 权限 Object Read & Write 已实测通过
- 建议关闭桶的公开访问（公开域不用，密文全部走预签名 URL）
- 无需开启版本控制、生命周期规则保持默认（保证删除即干净）
- 令牌一旦泄露（曾经出现在聊天/文档中）请立即在 Cloudflare 轮换，并同步更新环境变量

### 4.1 ⚠️ 必须配置 CORS（否则上传/下载在浏览器里必然失败）

预签名直传/直下是**浏览器直接连 R2**，不经过边缘函数，因此 R2 桶必须允许站点 Origin。Cloudflare 控制台 → R2 → 桶 → Settings → **CORS Policy**，填入（把域名换成你的站点域，预览域也要加）：

```json
[
  {
    "AllowedOrigins": ["https://vault.example.com"],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

验证方法：在站点里上传一个文件，浏览器 Network 面板里应看到对 `https://<account>.r2.cloudflarestorage.com/<bucket>/vault/...` 的 `PUT` 返回 200；若报 `CORS error`，就是这一节没配或 Origin 没写全。

> 这一步无法由代码/仓库下发（桶策略在 Cloudflare 侧），也是本地桩服务器能通过、线上却传不上去的最常见原因。

## 5. 定时任务（schedules）

已写入仓库 `edgeone.json`，部署时自动生效（字段：`name/cron/timezone/method/path/payload`）：

| 任务 | cron | 作用 |
|---|---|---|
| `self-destruct-sweep` | 每天 03:15 | 签到超时兜底扫描（免费套餐最低 1 天/次） |
| `audit-archive` | 每天 03:30 | 前一日审计日志归档到 R2 `archive/`（归档前校验链式哈希） |

> **免费套餐适配**：schedules 最低间隔为 1 天。自毁语义通过「**访问即检**」补偿——任何 `/api/state` 访问或登录尝试都会检查签到超时，超时即在后台立即销毁；每日 cron 仅兜底"无人访问"的情况。胁迫码销毁不受影响（登录请求内即时执行）。

## 6. 存储说明

- **笔记正文/标题/附件名**：加密后存 KV（单值上限 25MB，但受函数 1MB 请求体限制，正文实际约 750KB 明文）；不占保险库配额
- **笔记图片附件**：密文走 R2 `notes/` 前缀（预签名直传）
- **文件保险库**：密文 R2 `vault/`，配额只统计这部分；销毁时 `vault/`、`notes/` 一并清理
- 无 Blob store 需要创建

> KV `list()` 返回结构为 `{ keys:[{ key }], complete, cursor }`（与 Cloudflare 的 `{keys:[{name}], list_complete}` 不同）；代码里 `listAllKeys()` 已做双兼容并按游标翻页（单页上限 256）。

## 7. 验证清单（部署后逐项过）

1. 打开站点 → 显示"首次初始化"向导
2. 设置主口令 + 胁迫口令 + 签到超时 → 初始化成功（口令框为密码类型，输入不可见）
3. 用主口令解锁 → 进入保险库
4. 上传一个文件 → 列表出现，配额文本增长，**文件名正常显示（KV 中应为密文而非 base64 明文）**
5. 在行内"访问密码"框输入主口令 → 解密下载 → 内容与原文件一致（客户端解密验证）
6. 存储设置 → 修改配额（如 5GB→1GB）→ 保存成功
7. 新建笔记、保存、关闭、重新打开 → 内容一致；**左侧列表显示解密后的标题**；"详细信息"里能看到创建/修改时间与修改记录；上传图片附件后刷新仍可解密，附件名/上传时间正常显示
8. KV 控制台检查：`state_kv` 出现 `state:system`、`user:admin`、`hash:login:admin`、`hash:checkin`；`audit_kv` 出现 `audit:1...`
9. R2 控制台检查：`vault/` 出现密文对象
10. 手动调用定时任务端点验证鉴权（应 200 而不是 403）：
    ```bash
    curl -X POST https://<你的域名>/api/internal/sweep -H 'content-type: application/json' -d '{"token":"<INTERNAL_TOKEN>"}'
    ```
11. 手动测试自毁：设置里点销毁 → R2 `vault/`、`notes/` 与 KV `user:*`、`hash:*`、`nkey:*`、`file:*`、`note:*` 全部清空，页面显示"系统已永久锁定"，且可点"**重新初始化系统**"
12. 忘记密码流程：配置 `RESET_TOKEN` → 点"忘记密码"输入令牌 → 可重新初始化；验证后删除该环境变量，再试一次应被拒绝（403）
13. 日志页：应显示 5 列（时间/事件/用户/状态/详情）、"链完整性正常"徽标，详情为键值列表而非一段 JSON

> 🧨 **不要在已初始化后修改 `SESSION_SECRET`**：状态 HMAC 校验失败会被判定为篡改，从而触发全量自毁。确需更换，先走"销毁 → 重新初始化"。

## 8. 安全提醒

- `SESSION_SECRET` / `INTERNAL_TOKEN` / `RESET_TOKEN` / R2 密钥只放控制台环境变量或 CI Secret，严禁写入代码仓库
- 胁迫口令在登录框或签到框命中后，服务端立即删除密钥并清空密文，对外只返回与普通输错口令完全一致的「身份验证失败」（不进入任何假仓库），随后系统处于 `destroyed` 墓碑态，需重新初始化
- 15 分钟无操作自动锁定（纯前端，只清内存私钥、不删服务端会话、不刷新页面）；私钥与口令只存在内存，刷新/回跳仍需要重新输入口令
- CSP 与安全响应头由 `edgeone.json` 的 `headers` 下发（`script-src 'self'`，无任何第三方域名）

## 9. 性能与样式基线（v2.1 已修复）

部署后首屏应满足：

| 指标 | 基线 |
|---|---|
| 第三方请求 | **0**（Tailwind 已本地编译、Orbitron 字体自托管） |
| 首屏请求数 | 7（HTML、`style.css`、`tailwind.css`、`app.js`、`crypto.js`、字体、`/api/state`） |
| 本地实测 | TTFB ~15ms、DOMContentLoaded ~150ms、FCP ~240ms |
| 样式资源 | `style.css`（12KB）+ `tailwind.css`（10KB），均为本地文件 |

已修复的两个历史问题（如果你之前觉得"首页很慢 / 和原版不像"就是这两条）：

1. `style.css` 末尾 `@media (max-width: 767px)` 少了闭合 `}`，导致 `.hidden` 被包进媒体查询 → **桌面端四个视图同时显示**，页面完全不是原版布局
2. 通过 `cdn.tailwindcss.com` 加载 Tailwind（渲染阻塞、约 400KB）并在 CSS 里 `@import` Google Fonts（`Noto Sans SC` 会拉上百个分片），境内网络下表现为长时间白屏

排查回归时可用：

```bash
npm run build:css   # 有 class 变更时
node tools/api-smoke-test.mjs && node tools/crypto-test.mjs
```
